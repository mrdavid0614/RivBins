  Plan: Feature 03, heatmap dashboard and bin detail

  Scope

  Included
  - A heatmap of all 36 bins, grouped by aisle → rack, with each rack drawn as a
    level × position grid. Each cell is colored by its current score.
  - A "Recompute scores" button. It calls the existing POST /scoring/recompute,
    then the heatmap reloads.
  - A bin detail drawer with:
    - the current score and the factor breakdown (raw value, threshold,
      normalized value, weight, points; factor 5 shown as a %, per D-052)
    - the score history timeline, with the trigger for each change and the score
      delta
    - the last audit date
    - the pallets in the bin, with their product lines and quantities

  Not included
  - Searching a bin by code and the count flow (feature 05)
  - Pending-task badges and audit plans (feature 04)
  - Live updates or polling

  API changes (NestJS)

  Method: GET
  Path: /warehouse/layout
  Response: { warehouse: {code,name}, aisles: [{code, racks: [{code, levels, 
  positions, bins: [{id, code, level, position, score: number|null, 
  scoreComputedAt, lastAuditedAt}]}]}] }, sorted by position/level/position
  ────────────────────────────────────────
  Method: GET
  Path: /bins/:code
  Response: { id, code, aisle, rack, level, position, lastAuditedAt, 
  currentScore: {score, trigger, computedAt, factors:  FactorBreakdown[]} | 
  null, pallets: [{code, items: [{sku, name,  quantity}]}] }, or 404
  ────────────────────────────────────────
  Method: GET
  Path: /bins/:code/scores?limit=20
  Response: [{id, score, trigger, auditResultId, computedAt}], newest first

  - New modules warehouse/ and bins/, each with a controller, a service, and a
    pure mapper (Prisma rows → contract shape).
  - packages/shared: add WarehouseLayoutResponse, BinDetailResponse, and
    ScoreHistoryEntry (types only).
  - No schema changes and no migration.

  Web changes (Next.js 16)

  - page.tsx stays a server component. It fetches the layout through apiFetch,
    so the API stays server-side only (API_URL).
  - The drawer opens through a URL search parameter, /?bin=A-01-03. It's
    rendered on the server, so the URL can be shared, and the drawer closes with
    a link that drops the parameter.
  - Recompute is a server action: it calls the API, then revalidatePath('/'),
    and the button shows a pending state.
  - Components: Heatmap, RackGrid, BinCell, BinDrawer, FactorBreakdownTable,
    ScoreHistory, PalletList, and RecomputeButton (client). Plus
    lib/score-bands.ts for the color bands and a legend.
  - Before writing anything, I'll read the Next 16 docs in
    node_modules/next/dist/docs/ on server actions and searchParams, as
    AGENTS.md requires.

  Business rules applied

  - The heatmap color is based only on the current score. It goes green → yellow
    → red, and bins with no score are gray.
  - The breakdown shows the threshold and weight stored on each row, not the
    current config, so old scores stay explainable.
  - History is read from the append-only BinScore table and is never changed.

  Tests

  - Unit (Vitest): the layout mapper (grouping and sorting, bins with no score),
    the detail mapper (excludes lines with quantity 0? see Q5), and history
    ordering and limit.
  - e2e (seeded DB): layout returns 36 bins in 3×2 racks. /bins/A-01-01 returns
    6 factors whose points add up to the score. Unknown code returns 404.
    History is newest-first and respects limit.
  - Web: typecheck, lint, and a manual run of the app with a screenshot. There's
    no web test runner (D-022 covers only the API).
